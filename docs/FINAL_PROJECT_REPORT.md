## บทที่ 3: การออกแบบฐานข้อมูล (Database Architecture)

### 3.1 สรุป 11 ตารางในระบบ (เกินเกณฑ์ขั้นต่ำ 8 ตาราง)
1. `roles`: บทบาทผู้ใช้ (`customer`, `admin`)
2. `users`: บัญชีผู้ใช้งาน ข้อมูลติดต่อ และบทบาท
3. `categories`: หมวดหมู่หนังสือ (มี slug สำหรับ SEO/URL)
4. `authors`: ข้อมูลนักเขียน/ผู้แต่ง
5. `ebooks`: รายการหนังสือ ราคา ภาพปก และลิงก์ไฟล์
6. `carts`: ตะกร้าสินค้าของผู้ใช้ (1 ผู้ใช้ ต่อ 1 ตะกร้า)
7. `cart_items`: รายการหนังสือในตะกร้า (ป้องกันเพิ่มซ้ำ)
8. `orders`: คำสั่งซื้อ ยอดรวม และสถานะ (`pending`, `confirmed`, `cancelled`)
9. `order_items`: รายการหนังสือในออเดอร์ บันทึกราคา ณ วันที่ซื้อ (`price_at_purchase`)
10. `payments`: หลักฐานการชำระเงินจำลอง ภาพสลิป และสถานะการตรวจสอบ
11. `download_links`: โทเคนดาวน์โหลดที่ปลอดภัย เข้าถึงได้เฉพาะเมื่อออเดอร์ยืนยันแล้ว

### 3.2 การปฏิบัติตามหลัก 3NF
* **1NF:** ค่าข้อมูลเป็น Atomic Value ไม่มีชุดข้อมูลซ้ำซ้อนในแถว
* **2NF:** ฟิลด์ที่ไม่ใช่คีย์ขึ้นตรงกับ Primary Key ทั้งหมด ไม่มี Partial Dependency
* **3NF:** ข้อมูลผู้แต่งและหมวดหมู่ถูกแยกเป็นตารางเฉพาะ ขจัด Transitive Dependency
* **Business Compliance:** การเก็บ `order_items.price_at_purchase` ซ้ำกับ `ebooks.price` เพื่อคงประวัติราคาทางบัญชี
